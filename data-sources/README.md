# Data Sources

Catalogue of data sources used by this project. Each source should be added
below as it's identified, with enough detail for someone else to locate,
access, and understand its role.

Candidates below are drawn from `doc/project-2-ml-experiment-tracker-design.md`
§2.1, plus a broader macro/market layer (added 2026-08-10) for modeling
demand/pricing against the wider economy: global/regional GDP and inflation,
broad stock market indices, and individual stocks for companies across the
computer-hardware value chain (manufacturers, system builders, retailers,
distributors); plus a dedicated memory-market layer (also added 2026-08-10)
splitting DRAM/NAND demand and pricing across consumer, server, and
enterprise/data-center use.

## Format

For each source, capture:

- **Name** — short identifier
- **Description** — what the data is and why it's relevant
- **Location** — URL, path, or connection details
- **Access** — how to obtain/authenticate (if applicable)
- **License / usage terms** — any restrictions on use
- **Downloaded** — whether a sample has actually been pulled into this repo
  (path under `data-sources/<name>/`), or not (and why)
- **Notes** — freshness, known issues, caveats

## Traps found while building the revenue panel (added 2026-08-13)

Recorded here rather than inside the table cells above — each one silently
produces a *plausible* result, so they are worth finding before you write the
join, not after. `scripts/prepare_dataset.py` handles all four.

**Amends D12 — `sec-edgar-revenue/` covers six tickers, not three.** The design
assumed NVDA/AMD/Micron. The directory actually holds AAPL, AMD, DELL, HPQ, INTC
and NVDA, and a ticker needs a matching `company-stocks/` file to contribute
market features. That leaves **five usable tickers: AMD, DELL, HPQ, INTC, NVDA.**
AAPL has revenue but no stock file; **Micron has a stock file but no revenue
file**, so despite being named in the design it cannot appear in the panel at all.
The built panel is 224 rows across those five.

**`value_usd` in `sec-edgar-revenue/` is cumulative year-to-date, not quarterly.**
The discrete quarter is `cum(n months) − cum(n−3 months)` over the same
`period_start`. Summing the column as-is double-counts everything after Q1 and
still produces a monotone, believable-looking revenue series.

**The FRED PPI series marks gaps with a non-numeric token.** Read it through
`pd.to_numeric(errors="coerce")`. A bare `pct_change()` on the raw column
forward-fills across those gaps and hides them inside a plausible growth rate.

**Point-in-time dedup keys on `(ticker, period_start, period_end)`, keeping the
FIRST filing.** `fiscal_period` is not a key: the same window is labelled `Q3` in
a 10-Q and `FY` in the later 10-K. Keeping the *last* filing pulls in a
restatement published up to a year later — a look-ahead leak that scrambles the
time axis while every metric still looks fine.
